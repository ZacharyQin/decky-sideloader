# GitHub Sideload

Decky 插件，用于管理 GitHub 来源的插件：关联仓库、检查更新、选择历史版本、备份数据并通过 Decky 原生确认安装或卸载。

源码与设备版本均为 `0.2.0`，`debug` 模式。已安装到Steam Deck，等待用户根据实机表现审核，未推送或发布。[Changelog](CHANGELOG.md)按版本记录变更；`0.1.0`基线commit为`3e29851`，`0.2.0`功能commit为`8b6a85f`。

设备当前前端SHA-256为`024ce0ad610ac57026ad87b85d54d182385703cb4a47ca704f6669b5268ffe19`。16个程序文件及前后端版本核对通过，唯一刷新图标与首页加载已实机确认。用户最新配置、成功任务、接管记录和catalog保持，未对用户插件执行安装/卸载或点击手动刷新。本机184项前端测试、1187条断言、231项Python及类型/构建检查通过，不能代替用户实机审核。此前0.0.1/7988394a及任务52的独立复审、214项设备隔离回归属于历史验收，详细证据见[HANDOFF.md](HANDOFF.md)。

## 使用流程

- 导航、主要操作、插件列表和关键状态使用 SVG 图标，颜色跟随 Steam 主题。首页仅“检查更新”保留原生满宽主按钮，安装入口、显示范围与设置采用单焦点原生列表行。安装与任务页内部操作仍使用原生按钮，查看已有任务为次级导航行，不设置右侧 info 按钮。

- 首页显示插件列表，提供检查更新和从 GitHub 安装入口。行前复用已加载插件自身图标，缺失、禁用或身份歧义时回退通用图标；装饰图标不增加焦点。可更新箭头保留在状态文字旁，不替代插件图标。设置位于列表末尾。
- 已知商店插件默认由商店负责。独立“接管商店插件”入口要求确认目标仓库，原生冻结更新检查并完成回查后才进入本插件管理；仓库关联、已加载状态和旧记录均不代替接管授权。冻结不阻止手动商店安装，也不保证取消全部在途检查。
- “交还商店”只恢复该目标接管前的冻结策略，保留其他名称和设置。更换接管仓库先交还再接管；活动安装不能改变归属，未知或部分失败不自动重放。旧商店关联保留但不静默转为接管。
- 插件行整行聚焦，按 A 进入详情，按 B 返回。详情自动读取 Release，支持更新、同版重装和选择历史版本，另设“卸载并安装”。显式从详情返回先恢复原行一次，首次原生焦点后消费恢复意图；此后从顶部返回箭头向下按可见顺序进入，不持续跳回旧插件。
- 关联页默认填入插件名作为搜索词，展示最多 20 个仓库及说明、Star、Fork/归档标记。选中后须按“保存关联”，搜索和选择本身不会修改配置。
- 搜索词、结果和选择跨 QAM 关闭保留，B 可从选择预览返回搜索。也可直接填写 `owner/repo` 或 GitHub 链接；解除关联会停止自动探测和更新追踪，不卸载插件。
- 新装支持完整 GitHub 地址/`owner/repo` 直填，也可搜索后用原生下拉选择仓库。两种入口均先探查默认分支的 Decky 特征，单个插件进入版本预览，monorepo 多个插件须先选择目标目录。
- 探查核对同目录的 `plugin.json`、`package.json` 和 Decky 依赖或代码特征，支持仅前端插件及依赖被提升到工作区的项目，但后者仍须有自己的 Decky 入口代码特征。未识别、探查失败/不完整时不能继续；静态特征不代表作者可信或代码安全。
- 预览可选择版本、安装包和发布说明。最新发布无包不自动改选旧版，多安装包必须手动选择。monorepo 的 Release 属于整个仓库，安装前还会核对 ZIP 的插件名和包名与所选插件一致。
- 已识别为同仓库且同插件名称的已安装插件转入版本管理；同一 monorepo 的其他插件不会误跳转。ZIP 校验发现名称/目录碰撞时阻止新装，并提示从列表管理。
- 设置支持每 1、6、12、24 小时检查。定时完成后每轮通知更新、无需更新及失败等汇总；“定时检查通知”可独立关闭，关闭后仍检查并保存结果，不自动安装。设置只保留可点击的“最近定时检查”摘要，显示紧凑时间与非零重点计数；点击进入独立结果页查看逐项状态，仓库/长版本/完整错误留在记录详情。手动结果在首页，手动检查不覆盖最近定时结果。
- 已部署：匹配当前仓库和版本的可更新项及首页汇总使用独立绿色箭头 SVG，保留可更新文字和原生焦点。真实 Friendeck `0.7.5 → 0.7.7` 已验证；旧结果或失败项不显示更新标记。
- 安装任务状态跨 QAM 关闭保存。准备完毕后进入 Decky 原生确认；重新加载插件后不会自动重放安装。匹配完成证据、安装文件/变化标记和仓库关联持久化均成功后，任务自动结束并保留结果与备份；写入失败继续重试收尾，不重装。
- 状态文字使用原生语义色：失败红色、无法确认等警告黄色、更新/最新/成功绿色，普通及历史保留原生次级色。仅状态文字着色，插件名与版本保持原生颜色，不增加 info 控件。

## 下载、连接与来源识别

以下能力已部署，真机验收范围见下方。

- 安装任务显示实际下载字节、通道和尝试次数。有 Content-Length 时使用原生百分比进度条；总量未知时显示已下载 MiB 和不定进度。失败后停止，下载完成不代表安装成功。
- “检查更新”的图标在请求进行时旋转。关闭再打开 QAM 仍保留检查状态，不会重复发起；减少动态效果的系统偏好会关闭旋转动画。检查期间的列表刷新合并排队，结束后实际读取当前关联；普通列表读取成功不会清除检查错误，检查重试成功才清除。
- 设置的“网络连接”二级页提供“仅直连”“直连失败后使用 GH-Proxy”“仅 GH-Proxy”。默认仅直连，仅影响本插件的 GitHub 请求。自动模式只对可重试网络异常、5xx、429 或明确配额耗尽的 403 备用一次；普通权限错误、404、格式错误和校验失败不改走代理。
- 主设置包含定期检查、间隔、通知、唯一最近定时摘要、网络入口和唯一诊断内页入口。网络入口显示当前模式及最近使用通道，历史记录不保证当前连通；网络页在模式选择前默认展开完整第三方风险，并保留最近实际查询通道和时间。网络选择、保存中状态与页面跨 QAM 保留，迟到读取不能覆盖保存结果，保存失败恢复已确认模式并展示错误。
- 备用固定为 `https://gh-proxy.org/`，访问公开 GitHub API、raw 文件和 Release ZIP，不发送认证或 Cookie，不修改系统网络。第三方可见查询与下载内容，也可修改返回内容；TLS 和 ZIP 校验不保证作者或代码可信。进行中的安装准备保留开始时的模式，任务记录真实下载通道。
- GitHub 查询共用 60 秒、下载共用 180 秒绝对时限，覆盖 DNS 等待、连接、TLS、响应头、重定向与分块正文。超时或卸载取消会中断连接，卸载等待实际下载线程结束。系统 DNS 调用本身不可中断，最多 4 个只负责解析的 daemon 线程可能稍后完成；晚到结果不再建立连接或写文件，槽位占满时请求报错。
- 当前本地0.2.0只在点击刷新图标时读取官方商店，保留完整有效目录及匹配身份的历史关系，失败不覆盖已保存记录。历史商店正向记录持续阻止旧绑定自动接管，旧目录缺席不能证明新身份是非商店。
- 显式刷新失败且无成功目录时可读取官方[插件数据库登记](https://github.com/SteamDeckHomebrew/decky-plugin-database/blob/main/.gitmodules)辅助；普通读取不联网，登记不构成管理授权。没有本地事实的插件保持待确认，不猜下架或非商店。

## 问题反馈与诊断日志

从设置的“问题反馈 / 诊断日志”进入独立内页，点击“生成下载二维码”，下方可“刷新状态”。选择同一可信局域网的私有 IPv4 地址，生成本地二维码和临时 HTTP 链接，用手机或电脑下载当前 ZIP。默认只显示“诊断包已准备”和 KiB/MiB 大小，文件名和路径放在“文件详情”。提供复制链接和停止下载。实际原生按钮单次生成、268 CSS px 二维码机器解码及 A5 电脑通过真实 LAN 接收并校验 ZIP 已通过；没有把电脑接收或机器解码计为手机扫码、浏览器保存或物理手柄验收。

- 日志位于 SDK 本插件日志目录下的 `diagnostics`，单条 UTF-8 最多 8 KiB，活动文件及三个历史文件各 1 MiB，总计最多 4 MiB。只记固定事件、阶段、实际通道、耗时、计数及任务 ID，不记录 URL、headers、凭据、原始错误/调用栈、完整配置或备份内容。
- ZIP 位于 SDK 用户 home 下的 `Downloads/GitHub-Sideload-Diagnostics`，目录 `0700`，文件 `0600`。每包及全部展开成员最多 6 MiB，保留最近 3 包，旧包会轮替；加上日志稳态最多 22 MiB，构建时最多 28 MiB。不清理外来文件或安装备份，不跟随链接。
- 包含有限 JSONL、安全摘要及 manifest/成员校验。导出时再次过滤历史行，坏行只计数，超长物理行整行丢弃，不把尾部当成新事件；不包含原 SDK timestamp 日志或其他插件/系统日志。原 SDK 的精确文件 handler 在本插件进程内关闭，应用日志改由同一有界白名单 sink 接收，其他 handler 和全系统日志不改。
- 安装状态成功轮询不逐次记录；读取、解析或核验/关联/最终结果保存失败时，只记录固定 RPC 名、异常类型及耗时。诊断失败不替换原异常，不改变保存顺序。
- 导出期间按钮 busy/禁用，重复点击及 QAM 重挂共用同一意图，不重放。失败可显式重试；日志失效不改变检查、设置或安装结果。平台日志目录、用户 home 或安全文件条件不可用时安全失败，不回退到程序目录或 `/root`。

HTTP 未加密，持有链接的人可下载，仅用于同一可信局域网。每次最多5分钟、3次完整服务器传输，同时最多2条下载、4个客户端。HEAD不消耗次数；标记为预取的请求在开包前返回空400，不发送ZIP也不占额度。停止、过期、网卡失效和卸载会撤销服务；共享准备及活动/排空期间不能同时导出新包。传输完成不代表浏览器已保存或反馈已发送。二维码通过本地 `qrcode-generator@1.4.4` 生成，没有二维码或上传服务。

## 安装与备份边界

1. 重新确认安装包属于所选 GitHub Release，通过 HTTPS 下载到本插件数据目录。
2. 检查 ZIP 路径、单一目录、插件身份、版本、前端入口、重复路径、符号链接和大小。
3. 替换已有插件前，实际备份 Decky 标准 `settings/<folder>` 与 `data/<folder>`，校验备份完整性。权限不足或遇到不安全文件时停止，不自动提权。
4. 复核原插件与安装包未变化，再传本地包路径和 SHA-256 给 Loader 原生确认；由 Loader 负责卸旧、解压和加载。
5. 收到与本次提示及开始事件关联的 Loader 完成事件，且全包文件/身份和磁盘变化标记通过回查后进入核验收尾。保存仓库关联及成功结果后自动结束；任一步写入失败都不提前显示完成。目标插件运行功能仍须另行检查。

“卸载并安装”是独立模式，普通更新/同版重装仍保留。先原生确认开始准备，再下载、校验、备份，由第二次原生确认框告知备份范围与卸载风险；确认后只调用一次原生卸载。RPC 返回不算成功，必须回查目标程序目录及同名插件缺席，并复核 ZIP/备份，才提交一次原生安装确认。取消、失败、超时或插件重载不自动继续。标准 settings/data 不主动删除，但插件自身卸载钩子可能修改或删除数据；不自动恢复数据或回滚。

备份位于：

```text
$DECKY_PLUGIN_RUNTIME_DIR/installations/<operation-id>/data-backup.zip
```

相邻的 `plugin.zip` 是本次安装包，`operation.json` 保留当前任务状态。备份含实际配置/数据，文件权限为 `0600`。任务产物与备份保留供人工核对，不自动删除或回滚。

限制：

- 备份只覆盖上述标准目录，不覆盖插件自行写入的任意路径。插件运行中数据仍可能变化，不承诺应用级一致性快照。
- 不提供自动回滚。Loader 替换失败可能已移除旧版程序，应结合备份和旧版发布包人工恢复。
- ZIP 下载上限 128 MiB，展开与单次备份各 512 MiB，单包/备份最多 10000 个文件；准备前检查任务目录预算，总预算 2 GiB。超限会停止并提示位置。
- 缺少 LICENSE 或请求 root 权限的包显示警告，要求显式继续。多顶层目录、缺少前端入口、身份/目录变化会阻止安装。
- 仓库探查不构建源码，不把 GitHub 自动生成的源码 ZIP 当成发布插件。超出 20000 个目录项、10 个插件配置、40 个文件请求或 120 秒文件探查预算时停止；大仓库、被截断的树或损坏文件不能假定为扫描完成。成功探查最多缓存 10 仓库、5 分钟。
- Release 查询最多 1000 条，达到上限报错；GitHub 限流、离线等按插件记录为检查失败。
- Loader 不记录 zip 安装来源。列表依据 Loader 当前管理清单合并磁盘信息、独立的当前官方商店匹配及手动关联；商店查询失败不会被解释为没有非商店插件。测试/自定义商店频道识别尚未接入。
- 当前使用 Loader 的未文档化全局接口。接口/事件不可用时禁用安装/卸载，保留读取能力。
- 原生取消没有独立事件或响应丢失时，任务可能保持“尚未确认”。只取消已知未开始的待确认请求，不重复发送。取消或卸载结果未知时不能结束跟踪放行新任务；普通历史unknown的结束跟踪也不会取消Loader安装。

### Loader 当前管理清单

前端列表读取通过无参数 `window.DeckyBackend.call("loader/get_plugins")` 获取 Loader 管理集合，与磁盘包、商店来源分开合并。唯一名称磁盘项标记启用/禁用；仅磁盘项标记未登记；仅 Loader 项保留无目录的只读记录；多个同名目录全部保留并只读。包内版本不被 Loader记录版本覆盖，不一致只提示。

Loader 读取独立限时 5 秒。接口缺失、超时、重复名称或损坏快照显示独立错误，磁盘结果保留为管理状态未知；合法空快照不等于失败。Native-only/目录歧义禁止版本读取、安装、卸载和关联，新装探查同名项进入只读详情。稳定身份支持多个无目录项的焦点恢复。商店仍可能超时，仅显示实际未知/缓存状态；未修改网络、安装安全流程或持久设置。

本地测试与构建不代表已部署或真机通过；设备对照由主会话执行。

### 显式接管商店插件

商店已收录的已安装插件默认由商店负责，旧 GitHub 关联不代表接管。首页“接管商店插件”独立列出可接管项，确认仓库后选择“接管并暂停商店检查”。原生冻结回查通过后，本插件才检查和管理版本；此操作不安装或卸载程序。

详情可“交还商店”，停止本插件追踪，保留程序、数据及旧关联，仅恢复接管前的冻结策略。原本已冻结的插件继续冻结。接管失败、超时或重载时，结果保持未确认，只能显式回查或继续，不能通过旧报告、关联、新装或旧 ready 任务绕过。活动安装目标不可交还；Native-only 和同名多目录只读。

冻结不禁止手动商店安装，也不保证取消已在途检查。原生冻结数组不是跨应用事务。源码已实现，尚未部署或完成真机冻结往返验收。诊断跨设备下载已实现本地源码与回归，保留旧导出RPC；尚未部署或进行手机/电脑实机下载。
